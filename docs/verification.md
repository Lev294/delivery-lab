# Проверки

## 2026-09-17 — версия 0.2

Окружение: macOS 27.0, Apple M1 / arm64, 8 ГБ RAM; Docker Engine 29.1.3,
Compose v2.40.3; Docker VM около 4 ГБ RAM.

| Проверка | Фактический результат |
| --- | --- |
| Автоматические проверки API + настоящий PostgreSQL 17.11 | 15 passed, включая откат, конкуренцию и повторы |
| Ruff lint и форматирование | Пройдены локально и в тестовом образе |
| Полный Compose и настоящий HTTP через `scripts/demo.py` | Создание 201, повтор 200 с тем же ID, завершение и чтение 200 |
| Перезапуск приложения | Сохранённый заказ прочитан без изменений |
| Перезапуск PostgreSQL | Тот же заказ сохранён |
| Остановка PostgreSQL | live=200, ready=503, inventory=503; два последних ответа примерно по 3,01 с |
| Восстановление PostgreSQL | Готовность и чтение заказа восстановлены |
| Повтор миграций | Остаток не сброшен, исходные записи сохранены |
| Роль приложения | `rolsuper=false` |
| Чистый Git-клон `3b92503`, новый `.env`, новый пустой том | Начальный остаток 100, миграции и полный HTTP-demo прошли; Git-клон остался чистым |

Первый полный запуск обнаружил сбой исполнения shell-init через bind mount. Он заменён
на SQL-init; существующая пустая БД восстановлена применением SQL. Инициализация
нового пустого тома затем проверена из чистого клона. CI дополнительно запускает весь
Compose-стенд, поскольку ASGI-тесты сами по себе bootstrap не покрывают.

В тестовых зависимостях получены два предупреждения deprecation (httpx/Starlette и alias
AnyIO). Они не скрыты; тесты прошли. Это задача будущего обновления тестового клиента.

При проверке чистого клона использовался имеющийся кеш Docker-слоёв и скачанные базовые
образы; `.venv`, `.env` и данные БД исходного проекта не переносились. Это проверка
восстановления исходников, конфигурации и данных начального стенда, а не полностью чистой ОС.
Временный стенд и только его том после проверки удалены. Основной стенд оставлен работающим.

Исходный HTTP-сервис ранее проверен из чистого Git-клона. Это не подтверждает новую реализацию.

## Пока не проверено

GitHub Actions будет проверен после публикации; актуальный статус показан в badge README.
Нагрузочный предел, балансировка, gRPC, WebSocket и репликация пока не проверены и не реализованы.
